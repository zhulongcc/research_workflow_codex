# 文献阅读执行流程

本文件是检索、筛选、单篇阅读、独立核验与跨论文整合的唯一流程正文。
单篇内容与格式要求见 [reading_standard.md](reading_standard.md)；两者同时适用。
主代理先读项目规则、交接记录和 `research_scope.md`，恢复本次运行状态后再继续。

## 任务边界与额度

每次阅读任务最多执行 **3 轮**，首轮计为第 1 轮。以下是三轮合计的累计接纳额度，不是每轮名额，
也不是最终目录内论文数的限制。按相关性和必要性选择，不为了填满额度收录论文。

| 首次接纳类别 | 本次任务总额度 | 处理范围 |
|---|---|---|
| ultra | 40 篇 | 正式阅读与独立核验 |
| max | 30 篇 | 正式阅读与独立核验 |
| mid | 20 篇 | 正式阅读与独立核验 |
| inbox | 10 篇 | 筛选；不展开引用链 |

额度由主代理串行维护。先确认论文标题及公开来源并去重，再登记派发；子代理不能自行增加额度或开启新一轮。
正式论文按**首次正式派发等级**扣一次额度；后续 ultra/max/mid 间重分级只更新当前等级，不再次扣额，
也不退还原额度。降级、移除、失败或改为 inbox 均不返还已经使用的额度。

同一论文的重复版本、失败重试、返修、复核和跨轮续做，不重复扣同一种接纳额度。
inbox 首次派发使用筛选额度；首次晋级正式阅读时还须有相应的正式额度，原筛选额度保留。
已经扣过正式额度的论文，不因再次调整等级而重复扣额。额度不足时进入待办，不能为腾额度伪改等级。

`paper_type` 与 `priority` 正交。survey 是论文类型和单独存放的目录，不是第五个等级。
`survey + inbox` 仅按 inbox 筛选；正式 survey 依当前等级阅读，使用首次正式派发对应的额度。
不为综述重复建 ultra/max/mid 副本。

## 每轮由谁执行

主代理负责检索、初筛暂定级、额度、去重、分工、轮次整合与阅读推荐。
每篇论文分配一个作者子代理，由它连续负责该篇的材料、阅读、标注、修订与自检。
主代理必须实际调用当前可用的 `collaboration.spawn_agent`、`followup_task`、`send_message` 等工具自动派发，
按并发容量分批执行；同一轮的多个并发批次不算多轮。

单篇完成自检后，主代理另行派发**未参与该篇写作或修复的子代理**做独立核验。
核验者只读检查正文、原文、源码和标注，给出定位明确的问题；作者负责修复，核验者再核查受影响部分。
作者不能审核自己写的内容；主代理的汇总也不能冒充独立核验。一个核验者可核验多篇未参与写作的论文。
脚本只记录状态、额度和证据，不会自行调用 agent、上网检索或替代语义判断。

每次派发传递项目规则、论文标题与公开来源、选定版本、当前等级、相关研究问题、负责文件范围、阶段与阻塞项。
同篇同文件只由一个作者写；共用代码仓库由主代理协调文件写入，避免多篇作者同时修改同一源码。
子代理仅提交新发现候选，不自行扩张为新一篇正式阅读任务。

## 第一轮：检索、初筛与暂定顺序

1. 主代理按研究范围检索，记录候选身份、真实来源，去重论文版本和已有条目。
2. 依据题名、摘要及可得信息初筛并暂定 ultra/max/mid/inbox；这不是全文阅读结论。
3. 根据先修知识与当前研究问题生成暂定阅读顺序，保存在唯一内部状态文件；无需等全部单篇完成才有顺序。
4. 在剩余额度内派发候选。两次分级仅维护当前等级，不单独要求填写等级调整理由；
   既有 `priority_reason` 可保留，但不是派发、改级或验收的必填项。

## 单篇正式阅读的先后顺序

以下顺序是前置关系，不只是产物清单。可并行的是不同论文，以及同阶段互不依赖的材料获取。
不可跳过同篇前置阅读而提前写结论或批注。

| 阶段 | 作者执行 | 进入下一阶段前的条件 |
|---|---|---|
| 材料获取 | 取得 PDF、同版 LaTeX 及可用算法源码 | 来源、身份和选定版本明确；缺失如实记录 |
| 全文快读 | 通读全文结构、方法、结果与局限，确认等级 | 更新当前等级；正式接纳额度有效 |
| 解读来源匹配 | 按官方标题、arXiv/DOI 查找对应 Paper-Notes 页面 | 精确匹配后复用；未找到则依单篇标准独立撰写 |
| 贡献提取 | 摘录作者 Highlights 或贡献原句并定位 | 原文可回查，不依赖已有中文译文 |
| 译文与初稿 | 完成规定译文、详细 note 和 qa 六问答案初稿 | 翻译与解释可回查；外部解读已纠错并标来源 |
| 源码阅读与对照 | 先读主链路，再注释关键块并双向标注 | 五类流程已核查，真实差异与未知缺口分开 |
| 正文修订 | 据代码对照修正 note 模块解释和 qa 答案 | 差异嵌入相关方法；六问只在 qa，结论整合进 note |
| 作者自检 | 检查文本、格式、链接、标注及检查报告 | 无未处理的自检错误，证据可以交给核验者 |
| 独立核验与返修 | 核验者定位问题，作者修复并重新自检 | 独立核验通过，或明确保存阻塞与下一步 |

材料必须与本次确认的论文和代码版本对应，不自动换成线上新版本；不记录 SHA256。
同版 LaTeX 无法获取时，记录来源限制，以 PDF 继续；PDF 不可获得或必要材料不能确认时，停在材料阶段。
公开仓库不可访问与确无公开代码不同，不能把暂时取不到代码写成“不开源”。

全文快读用于重新确认等级，不等于精读完成。若确认仍为 inbox，则只交筛选结果，不继续译文、六问、
代码标注与引用链扩展；晋级正式前由主代理确认正式额度。正式作者先独立提取原文贡献并存入 note，
再逐条翻译，将同一译文写入 note 的对应原句后和 translation_zh 的 Highlights，随后完成详细 note 与 qa 初稿。
原句提取不依赖译文定稿，避免“先完成翻译”和“翻译等待 note”相互依赖。
准确匹配的 Paper-Notes 可作为内容底稿，按单篇标准直接复用、核验和必要纠错；不能代替原文阅读。
未找到或无法获取时按单篇标准的详细写作指引生成，不等待外部页面，也不把本项目指引称为作者 prompt。

代码阅读先走 README、配置、输入、模型、输出，再读数据、目标和更新；看懂后才添加中文解释性注释。
直接在现有源码关键代码块旁注释，不逐行注释、不重构、不改变行为，无须专用分支。
PDF、源码和映射表按 [code_annotation_guide.md](code_annotation_guide.md) 双向对应。
没有公开代码的论文记录检索依据，完成适用阅读即可；静态阅读不要求安装模型环境或运行实验。

代码对照后修订 note 与 qa，不另外生成重复的单篇总结文件。note 按材料、Highlights、一句话总结、
背景与动机、方法详解、实验与消融、局限与启发组织；代码差异融入相关模块，Highlights 逐条英中配对。
不设文末来源章；复用内容的作者、原文链接、许可链接与“已改编”集中为材料区的一条来源。
六问完整问题、答案及依据统一放 qa，不在 note 重复。独立核验同时检查详细 note 的解释和 qa 答案，
以及两处 Highlights 译文一致性、导入解读的论文身份、数字/公式纠错和材料区必要归属。
保持译文忠实于论文，不能为了匹配实现而改写作者原意。

## inbox 的终点与晋级

inbox 是有限的筛选工作：核实论文身份与来源、阅读足以判断相关性的内容，给出当前等级和是否需要补读。
筛选发现的引用不自动扩展为下一层候选。独立子代理只核验筛选依据，不要求完整译文、六问答案或代码标注。
不能把筛选完成写成精读完成；也不能因仓库里有骨架而省略筛选。

需要晋级时交主代理登记首次正式额度，再从正式阅读对应阶段接续。保留已取得的真实材料，
不重建重复条目、不退还筛选额度。因额度不足暂缓的晋级留在待办。

## 新发现论文与后续轮次

正式阅读或独立核验发现需要补读的论文时，交回候选记录，不在当前作者任务里无限追读。
每个候选至少包含：论文标题及 DOI/arXiv 等公开身份、来源链接、发现它的论文/代码关联位置、具体补读需要。
只有以下必要性支持自动安排正式补读，普通背景引用不自动触发全文阅读：

| 必要性 | 需要说明的关联 |
|---|---|
| 理解核心模块 | 不补读会缺少哪个核心定义、推导或设计依据 |
| 实现关键依赖 | 哪段实现依赖它，当前论文或仓库为何不足以解释 |
| 直接比较工作 | 与当前方法直接比较的设置、主张或证据是什么 |

主代理在每轮核验后合并新发现与未处理的积压候选，去重并按研究范围重新排序、分级，更新暂定阅读顺序。
本轮新发现最早进入下一轮；不能把并发批次当作新轮，也不能把下一轮工作插入当前作者任务绕过轮次。
已开始论文的修复与复核属于原有阅读工作，不产生新的论文额度。

继续条件是：尚未到第 3 轮，且存在当前可处理、必要并能在剩余额度内接纳的候选。
达到 3 轮、没有可处理候选、剩余候选均无法在额度内接纳，或剩余工作受外部条件阻塞时停止扩展，
留下明确待办、材料缺口与恢复位置，不为凑数增加搜索或静默新建运行来重置额度。
主代理结束时整合所有已经核验的单篇结论，给出当前版本的方向关系、阅读推荐与比较。

## 阅读完成与实现一致性

阅读是否完成，与作者代码是否忠实实现论文分开记录。已核实的实现差异、缺失实现或原文歧义，
只要定位、影响和证据完整，并经独立核验确认，就可以作为阅读结论收尾；不能宣称实现完全一致。
未确认的对应、未取得的必要证据、尚未解释的差异仍是未解决缺口，保持 partial / blocked。
不为了消除差异修改算法，不把未知缺口换名为“已核实差异”。

结构检查报告的 `workflow_ready` 只能作为候选信号。主代理还须确认本篇作者与核验者不同、
核验依据对应当前修订、返修已再次检查、无未解决缺口，才可结束正式阅读阶段。
机器产物与内容要求见 [reading_standard.md](reading_standard.md)。

## 阻塞、恢复与内部记录

所有内部执行状态只保存到单个 `.workflow/execution_state.json`：运行与条目的内部引用、作者/核验者身份、
轮次、额度、阶段、候选积压、初筛历史、完整审阅报告、修复和证据均内嵌于此。状态由主代理串行更新。
多次运行也共享这一个状态文件中的独立记录，不创建按运行或条目标识命名的目录、报告、备份或第二份台账。
正式目录依据论文标题或方法名生成可读名称；论文元数据用 `title`、代码条目用 `name`，关联使用真实路径。
读者正文、路径、元数据、HTML 属性、源码及 PDF 中不得保留生成的执行标识或映射流水号。
生成时就使用标题、方法名、章节/公式与可读路径构造交付内容，不先输出完整内部任务对象再事后删标识。
概念文档可以说明临时输入字段，但不能把实际内部标识填进项目内其他文件或示例。
任何阶段均可标 blocked，说明缺什么、影响什么、已经做到哪和恢复所需条件。
恢复后从原阶段继续，沿用内部记录与已扣额度；不要重跑已经完成且未受影响的步骤。
上游材料、译文或实现理解变化时，重查受影响下游产物，再自检并交独立核验，不沿用过期结论。
材料阶段会登记论文身份、PDF/LaTeX 版本与源文件状态、代码提交及实际 HEAD；后续阶段均与登记值核对。
更换论文来源、版本、源文件或代码提交前，必须显式回退材料阶段并重新登记，不能只改 metadata 后继续。
回退保留首次扣额与全部作者历史，使下游草稿、映射、自检和独立核验失效。

用户已有原始笔记、个人 Insight、问答和 PDF 批注不属于可清理的中间产物，不覆盖、不删除。
内部记录与读者正文分开；分阶段状态不散落到 note、translation 或最终推荐中。
机器核查所需的 `reading_manifest.json` 和映射 JSON 可以保留在论文目录，但只能含可读标题、公开版本、
实际位置和不含内部标识的证据；不作为 HTML 阅读正文展示。manifest 用 `paper_title`，
代码覆盖用 `locations`，映射靠章节/公式与源码路径定位，不能把内部引用藏进文件名或引用地址。

## 面向读者的最终产物

note、translation、qa、代码导读和跨论文 reading_guide 只呈现最新定稿。
不展示初筛历史、前后草稿、审阅意见、修复过程、验收横幅或调度信息；保留必要来源、版本、
原文定位、真实实现差异、当前局限和适用范围。未运行实验等影响判断的事实仍需诚实说明。
最终阅读推荐依据已核验理解生成；未完成或尚未核实的引用不得伪装成已经读完。

按 [reading_standard.md](reading_standard.md) 同时交付 Markdown 与三线表 HTML，
每行表格全部单元格可见文字合计不超过 160 字符。原文长引文和解释放表外，不用换行绕过。

## 本地状态命令

以下命令由主代理在实际完成对应工作后串行调用，不能用填写状态代替工作。
`<skill>` 为技能安装目录，`<项目>` 为科研项目根目录。CLI 可使用运行、条目、作者和核验者的临时内部引用；
这些值只从运行时传入，并持久保存到唯一状态文件，不复制到交付文件、目录、正文或元数据中。
先通过 collaboration 创建真实作者，再用返回引用登记 dispatch；独立核验同理。

候选和阶段证据 JSON 必须从标准输入 `-` 传入，或使用项目外的临时文件。主代理先在内存构造 JSON，
通过工具的标准输入传给命令，不在项目内写含执行标识的输入文件。项目外临时文件导入后不作为交付或引用，
只清理本次代理创建的临时文件，不删除用户提供的原始材料。

```bash
python <skill>/scripts/literature_run.py --project <项目> init <内部运行引用>
python <skill>/scripts/literature_run.py --project <项目> --run <内部运行引用> candidate -
python <skill>/scripts/literature_run.py --project <项目> --run <内部运行引用> dispatch <内部条目引用> --agent <作者运行时引用>
python <skill>/scripts/literature_run.py --project <项目> --run <内部运行引用> advance <内部条目引用> <阶段> --evidence -
python <skill>/scripts/literature_run.py --project <项目> --run <内部运行引用> status
```

候选输入提供 `title`、`source`、`need`、`priority` 和 `paper_type`；有公开 DOI 或 arXiv 时提供相应来源字段。
临时输入可含台账要求的内部引用，导入后只进入唯一状态文件，不能再写回论文元数据或用来命名正式目录。
`need` 说明具体补读需要，扩展候选标明前述三类必要性之一，并提供关联论文的真实章节或代码位置。
本轮新发现最早下一轮派发；后续轮登记既有积压须明确 `origin: "backlog"`，不能冒充积压提前处理新发现。
两次分级没有单独的调整理由字段要求。
输入的完整字段协议通过 `candidate --help` 和 `advance --help` 查询；字段名属于工具接口，实际执行引用只进入唯一状态文件。

正式阶段依次为 `materials → classified → drafted → mapped → self_checked → reviewed`；
inbox 为 `screening → screened`。贡献提取、必译内容、详细 note 和 qa 六问初稿进入 drafted；
源码标注与 note/qa 修订完成后再自检。
证据中的真实论文、代码与源码路径相对项目根目录，不能包含内部执行标识。

| 阶段 | 内嵌证据要求 |
|---|---|
| materials | 可读论文目录、PDF/LaTeX 版本、真实源码、开源情况、代码路径及材料说明 |
| classified | 全文快读结论与当前 priority；正式改级不再扣额 |
| drafted | 原文贡献、译文、详细 note 与 qa 六问答案已齐备的说明 |
| mapped | 五类对应及据此修订 note/qa 的说明；差异与未知缺口分开 |
| self_checked | 当前修订的作者自检及实际产物检查结论 |
| reviewed | 真实独立核验者的运行时引用与当前修订的核验正文 |
| screening / screened | 筛选结论；独立核验者及筛选核查正文 |

各阶段报告以 `report_text` 直接传正文，或通过 `report_file` 导入项目外临时文件。
独立核验使用 `review_report_text` 或 `review_report_file`，导入后完整正文内嵌唯一状态文件，
不保留外部报告路径作为交付引用。核验者内部引用也只在内存输入和状态文件中出现；
不能复用作者自检报告冒充独立检查。

materials 另填 `paper_dir`、`pdf_version`、`latex_version`、`latex_files`、`open_source`；
开源时填 `repo_entry`。这些是可读产物路径或公开版本，不是内部条目标识。
LaTeX 不可得时可让 `latex_files` 为空，同时提供 `latex_unavailable_reason`，
并通过 `latex_search_text` 或项目外的 `latex_search_file` 记录实际查找依据，仍须有可读 PDF。
classified 另填 `priority`。版本须与标题、公开来源及已有材料登记一致，不能只改说明绕过核对。

```bash
python <skill>/scripts/literature_run.py --project <项目> --run <内部运行引用> block <内部条目引用> --reason <阻塞说明>
python <skill>/scripts/literature_run.py --project <项目> --run <内部运行引用> resume <内部条目引用>
python <skill>/scripts/literature_run.py --project <项目> --run <内部运行引用> revise <内部条目引用> --reason <修订说明>
python <skill>/scripts/literature_run.py --project <项目> --run <内部运行引用> revise <内部条目引用> --from-stage materials --reason <换源说明>
python <skill>/scripts/literature_run.py --project <项目> --run <内部运行引用> defer <内部条目引用> --reason <暂缓说明>
python <skill>/scripts/literature_run.py --project <项目> --run <内部运行引用> reject <内部条目引用> --reason <排除说明>
python <skill>/scripts/literature_run.py --project <项目> --run <内部运行引用> close-round --reason <本轮结论>
python <skill>/scripts/literature_run.py --project <项目> --run <内部运行引用> finalize --reason <停止依据> --summary related_work/reading_guide.md
```

block/resume 保存并恢复原阶段。默认 revise 使旧核验失效：正式条目回到 classified 后重新提交
草稿、映射、自检和独立核验；inbox 回到 screening 后重新核验。更换作者时只在台账登记运行时引用。
`revise --from-stage materials` 清除材料及全部下游阶段证据，回到 dispatched，重新完成 materials 起的流程；
首次扣额与作者历史仍保留在状态文件。默认 `--from-stage drafted` 即上述回到 classified 的内容返修。
已关闭但尚未 finalize 的运行，可因修复重开当前逻辑轮，不增加轮数，也不产生第 4 轮。
晋级已筛选 inbox 时，以 `dispatch --priority <正式等级>` 登记首次正式额度，不重复消耗筛选额度。

defer/reject 只处置尚未派发的候选，分别记录暂缓和不纳入的具体原因，不能伪写为外部阻塞。
close-round 检查本轮任务已独立核验或明确阻塞；如有可接纳的下一轮候选且未达到上限，会进入下一轮。
finalize 需要真实的最新跨论文推荐及公开来源或可读路径，保留停止依据和待办，不能以空模板宣称完成。
状态脚本可识别部分产物变动，但不能验证代理身份或语义，主代理始终对实际派发和内容核验负责。
若发现旧版按运行分目录保存的状态，先将原轮次、额度和报告合并到唯一状态文件，再移除旧目录；
工具会拒绝在旧运行尚未迁移时重新初始化，防止无意清零额度。

## 收尾时检查执行标识泄漏

在生成阅读页面和结束运行前，针对台账内登记的内部标识复查本次生成或迁移的阅读交付：
目录与文件名、正文与链接、JSON 字段、HTML 属性、代码注释，以及 PDF 批注的正文、标题、作者和元数据。
本次新建的临时报告、迁移副本和缓存也不能泄漏执行标识；检查是生成时约束的复查，不是默认事后清洗流程。
发现残留时，以论文标题、方法名、章节/公式或可读路径替换工作流生成的引用，并修复关联链接。

检查不删除官方 DOI、arXiv 编号、代码 commit、原文公式编号、官方仓库名称或源码既有变量名。
六问编号、原文条目顺序及有明确含义的章节名称不属于执行标识。保留用户原始笔记内容，
修复其中由本工作流自动插入的执行引用时只调整引用，不改动用户观点。
本次迁移范围限于阅读产物与新 workflow；保留其他任务上下文和既有历史备份，不扩展为全项目历史清理。
