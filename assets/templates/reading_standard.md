# 论文阅读交付标准

本标准规定正式阅读的单篇内容与格式。执行顺序、额度、子代理分工及轮次见 [reading_workflow.md](reading_workflow.md)。
`priority=ultra/max/mid` 采用同一最低门槛；等级只表示相关度和额外分析深度。
survey 是类型，与 priority 正交；`survey + inbox` 仅筛选，不要求正式精读产物。
inbox 不展开引用链，不能把筛选或保存骨架称为阅读完成；晋级按执行流程登记正式额度。

## 版本与来源

只使用本次确认的最后一版 PDF 和选定的对应代码；记录来源、采用版本和日期，不记录 SHA256。
不因发现在线更新而覆盖已有笔记。论文源码与选定 PDF 同版，原始材料保留在 `source/raw/`。
找不到源码不编造；以 PDF 为依据继续可以完成的阅读任务，并说明来源限制。

所有重要结论注明可回查的位置：PDF 页码、章节、公式、图表或代码文件及行范围。
以下内容分开标注，不把作者主张、实验证据和自己的判断混为一谈。

| 标签 | 内容与依据 |
|---|---|
| 作者原文 | 保持原文措辞，给出论文位置 |
| 中文翻译 | 忠实对应作者论述，保留术语、限定条件和符号 |
| Agent 总结 | 压缩解释原文，保留出处，不扩张结论 |
| Agent 分析 | 推断、质疑与建议，标明证据及不确定性 |
| 社区评价 | 可选；记录评价者、链接、日期和被评价对象 |

社区评价不要求主动搜集到才能通过；未找到可信评价可以省略。不能伪造社区共识。

## 每篇最低交付

| 产物 | 必需内容 |
|---|---|
| `note.md` | 材料、英中配对 Highlights、一句话总结、背景、方法详解、实验与消融、局限与启发 |
| `translation_zh.md` | 摘要、Highlights、方法、不足、未来展望的规定译文与总结 |
| `qa.md` | 六问的问题、Agent 完整答案及依据；用户个人交互区留空 |
| `reading_manifest.json` | 机器证据记录；区别已核实差异与未知缺口，不展示到阅读正文 |
| `reading.html` | 汇集阅读内容的 HTML 阅读版，表格呈三线表 |
| 开源工作的标注 | 同版批注 PDF、真实源码注释、`code_map.md` 及代码导读 |

模板中的占位符、空表、标题和“尚未开始”只表示待处理。旧条目如果缺失必需内容，应显式记录为
未完成并补齐；不能因为曾经下载、进入正式目录或已有 metadata 而默认为完成。
分阶段状态、初筛历史、作者自检和独立审阅记录放唯一内部状态文件。最终正文只呈现最新定稿，
不带验收横幅或过程记录；保留必要来源、版本、真实差异和当前局限，不修改用户原始笔记。
唯一内部状态文件为 `.workflow/execution_state.json`。内部运行、论文、仓库、作者与核验者标识，
以及各阶段和审阅报告，只保存在该文件；不能另写带这些值的报告、元数据、路径或备份。
正式目录根据论文标题或方法名命名。论文元数据使用 `title`，代码条目使用 `name`，相互关联使用真实路径。
官方 DOI、arXiv 编号、代码 commit、原文章节/公式编号及可读名称是必要来源信息，必须保留。
从生成时就只导出这些读者字段，不先把完整内部任务记录写入交付再清洗；真实执行标识不填进项目内示例。

## note.md：可连续阅读的详细精读

note 固定使用以下七个二级章节，按此顺序组织正文：**材料 → Highlights → 一句话总结 → 背景与动机 →
方法详解 → 实验与消融 → 局限与启发**。综合理解整合进这些章节，不另建重复的单篇总结文件。
六问的问题、完整答案和依据统一放 `qa.md`，note 不重复设置六问或答案摘要表。
先提取论文作者贡献原句，再完成主要部分翻译、详细 note 与 qa 初稿；读懂源码并对照后修订受影响内容，
最后自检与独立核验。各阶段前置关系见执行流程。

### 优先复用准确匹配的 Paper-Notes 笔记

正式阅读时先按论文完整标题和官方 arXiv/DOI 查找 [Paper-Notes](https://github.com/zhaoyang97/Paper-Notes)
的对应页面，核对笔记链接所指的原论文、作者与任务，不能只按方法简称或相近题目匹配。
找到且可获取时，直接复用经核验的内容与表达，保留其详细解释，只做适配本页结构和表格的排版、
必要纠错及缺失补充；不要把详细笔记重新压缩成几句提纲。

Paper-Notes 是二手解读，最终依据始终是本次选定同版论文和代码。逐项检查数据、单位、公式、参数、
阶段顺序、比较条件与结论强度；无法被原文支持的内容应纠正、删去或明确转为有依据的分析，不能照抄成事实。
补齐作者原文 Highlights、原文定位、当前课题所需解释、源码对照和 qa 答案。星级评分、泛泛赞誉和网站自动
推荐列表不导入；有依据的比较或启发保留到对应正文中，不能将自动推荐列表当作已读引用链。

页面不存在、无法取得或不能确认是同一篇论文时，记录查找结果到唯一内部状态文件，并按下述写作指引
从选定论文独立生成。没有 Paper-Notes 不构成阻塞，也不降低 ultra/max/mid 的共同内容门槛。
这些指引由本 workflow 根据 [Gaussian Haircut 解读样例](https://github.com/zhaoyang97/Paper-Notes/blob/306a06129d960c08e98b01fe20d60fea7be0a0a5/docs/ECCV2024/3d_vision/human_hair_reconstruction_with_strand-aligned_3d_gaussians.md)
的组织方式提炼，**不是作者公开的生成 prompt**。作者在
[公开回复](https://github.com/zhaoyang97/Paper-Notes/issues/1#issuecomment-5155487311)中说明先让 agent 写笔记，
再把流程总结为可复用 skill；本次未取得该 skill 的公开正文，不得把我们编写的指引归为作者原文。

### 七个章节如何写

**材料。** 用简短链接列表或表格提供选定论文、可用源码、代码导读、批注 PDF、译文与 qa 的阅读入口。
必要版本附在材料链接旁，不单开“版本与阅读范围”，不放开头使用提示或验收说明段。
实际复用外部解读时，必要归属也集中为材料区的一条简短来源说明，不另设文末来源章。

**Highlights。** 有正式栏目时逐条保留论文作者原文；没有时，从摘要、引言或贡献列表摘录贡献原句，
简洁给出页码/章节即可，不写“非独立 Highlights 栏目”等说明，也不加“作者原文”副标题。
每条英文原句后紧随忠实中文译文，成对呈现；不得用 agent 改写或 Paper-Notes 的评价冒充论文原句。
长句使用英文引用加中文段落，不截断关键限定条件，也不把英中长句塞入超过 160 字符的表格行。
`translation_zh.md` 仍保留完整 Highlights 翻译；两处使用同一译文，顺序、内容与原文定位保持一致。

**一句话总结。** 准确连接问题、核心设计和得到支持的结果，用一句完整的话概括贡献。
不以“巧妙”“首次”“领先”等未核实修饰代替信息，不把实验条件省掉后泛化结论。

**背景与动机。** 用有联系的段落解释领域已有做法、具体痛点、现有方法为什么受限、本文要解决的矛盾、
目标与切入角度。必要术语先解释，前驱工作只做经过核验的比较；不能仅罗列论文名字和“效果更好”。
清楚区分作者提出的动机和本项目对问题的理解。

**方法详解。** 先讲整体框架：任务输入、表示、阶段之间的中间产物与最终输出，训练、逐场景优化、
推理分别发生在哪里。随后按实际计算顺序或依赖关系拆解关键模块。每个模块都解释解决哪个具体问题、
承担什么功能、输入怎样被处理为输出、为什么采用这个设计，以及它如何影响后续步骤。
模块较复杂时用完整的长段落说明机制与因果关系，不能用只有“功能/公式/结论”几个短句的表格代替。

给出理解核心机制所需的公式，说明变量、约束、优化对象、监督来源、冻结与更新的参数，以及损失如何
作用于表示或模块；数值设置只写原文或代码中能定位的内容。解释从设计到预期效果的路径，并在实验章节
连接对应证据，构成“问题—设计—机制—证据”的叙述。不是所有论文都需要同样的模块名或训练术语：
理论工作解释假设、推导和命题，数据集工作解释构建、质量控制与使用协议，综述解释组织依据和覆盖范围。

源码对照发现嵌入对应模块或优化阶段的段落，采用“论文描述…；所选实现…”的清晰区分，并链接准确
章节/公式及代码位置。保留真实差异的条件、影响和未知点，不把相距较远的总表当成唯一解释。
详细定位仍放 `code_map.md`，不开一个重复全部代码导读的 note 大节，也不为对齐代码改写论文原意。

**实验与消融。** 先说明数据、任务设置、比较对象与评价口径，再给主要结果、消融和它们支持的结论。
每个关键数字注明来源与单位；时间/速度比较保留硬件、任务或预算条件。区分定量、定性图示和作者解释，
没有数字的可视结果不能编成数值表。消融说明改变了什么、其余条件是什么、观察到什么，以及能支持哪项
机制；不能把相关现象写成未被实验排除的唯一因果解释。作者未给消融或缺少某种证据时如实说明。
对比表用于并列条件与结果，每行可见文字合计 ≤160 字符，较长的实验解释放表后。

**局限与启发。** 归纳作者明确的局限与展望，并将未被实验覆盖的范围、源码已核实差异的影响、
本项目可能借鉴的设计分别讲清楚。独立推断标为 Agent 分析，说明依据、适用条件及还需要什么验证；
“未报告”不等于“不能做到”。有可信社区评价时在相应段落标明评价者、来源、日期和对象，
没有则省略，不为凑评价补泛赞，也不把建议研究方向写成已证实结果。

### 材料区的简短归属

note 不设置“来源与改编说明”章节。实际复用 Paper-Notes 时，在材料区集中保留一条简短说明，
包含作者、对应原文链接、[许可链接](https://github.com/zhaoyang97/Paper-Notes/blob/main/LICENSE)及“已改编”。
格式示意：`来源：zhaoyang97 · Paper-Notes 对应原文链接 · CC BY-NC-SA 4.0 许可链接（已改编）`。
链接须指向实际复用的页面。未复用则不生成这条归属，也不将独立撰写内容标成外部改编。

改编内容继续遵守原许可，不把该许可扩展为整个 workflow 仓库的新许可证。必要论文定位和实现差异
仍在相关正文保留；详细搜索、纠错和改编记录只进入 `.workflow/execution_state.json`，
不另建公开 provenance 文档或用其他文末章节重复这些过程信息。

## qa.md：六问、完整答案与依据

Agent 必须先完成六问，每问在 qa 中有明确的 Q1–Q6 标题、完整问题、实质答案和可回查依据。
答案与依据应清楚可辨，可用“答案”“依据”标签，也可在答案段末简洁标注依据；复杂答案用段落展开。可以链接 note 的相关解释，但不能只写
“见 note”或用问题导航表代替答案。需要简答表时只作导航，不在 note 复制六问。

1. **Q1：论文要解决什么问题？** 说明问题设定与约束。
2. **Q2：方法的输入、输出是什么？** 区分必要输入、预处理和最终产物。
3. **Q3：训练时学什么？更新什么参数，用什么监督？** 说明参数、监督和目标，区分预训练与逐场景优化。
4. **Q4：推理时做什么？输出如何使用？** 说明执行步骤、优化/采样过程及输出用途。
5. **Q5：证据是什么？对应哪些实验、公式或图表？** 定位依据，注明比较条件及支持范围。
6. **Q6：什么尚未得到证明？** 区分作者明确局限与 agent 判断，避免“没报告”等于“不能做”。

综述、理论、数据集论文对训练/推理不适用时仍保留 Q3/Q4，解释不适用原因，并回答构造过程、
假设与覆盖范围。不能留空或以“不适用”两个字代替阅读。
“Agent 后续问题”区可记录真实未解决问题与研究方向；用户个人 Insight、GPT 对话和个人理解区保持空白，
不替用户写体验或伪造交互。

## translation_zh.md：主要部分必须译完

固定使用“摘要”“Highlights”“方法”“不足”“未来展望”五个章节，并记录原文定位和已译范围。
最低要求是主要部分，不能声称已完成全文翻译；全文翻译是可追加任务。

| 部分 | 翻译要求 | 独立总结 |
|---|---|---|
| 摘要 | 全部摘要，保留限制条件与量化描述 | 用中文简述问题、方法与结果 |
| Highlights | 已提取的原文贡献逐条完整翻译，与 note 的配对译文一致 | 说明贡献间的关系，勿新增主张 |
| 方法 | 覆盖核心流程的关键段落；定位章节、公式、图示 | 输入、步骤、输出及关键公式变量 |
| 不足 | 翻译作者相关论述 | 作者局限总结；agent 分析另标 |
| 未来展望 | 翻译作者相关论述 | 作者未来工作总结；agent 建议另标 |

“关键方法段落”不能仅选抽象介绍：须让读者理解主要表示、学习/优化目标、训练与推理如何连接。
保留必要数学符号并解释变量，不用中文概述替代应译段落。明确列出未译的正文、附录和图表说明。

作者未明确讨论不足或未来展望时，在对应章节写“原文未明确讨论”，并说明核查的章节范围。
不需要编出作者没有写的译文；agent 推断必须置于“Agent 分析（非原文）”，不得混入翻译与作者总结。

## 表格与 HTML

Markdown 使用通用 pipe 表格，HTML 阅读版使用三线表：表顶线、表头底线和表底线，无竖线。
不能承诺所有 Markdown 阅读器都按三线表显示，所以 Markdown 与 HTML 同时交付。

每一条表格记录中，**所有单元格可见文字合计 ≤160 个 Unicode 字符**。中文、字母、数字、标点、
空格各计 1；链接只计显示文字，Markdown/HTML 格式标记、列分隔符和对齐行不计。表头也遵守限制。
渲染时不可见的格式空白不计；可见内容中的连续空白按实际显示的一格计。`<br>` 或源码换行仍属同一行，
不得拆换行规避限制。工具按这一口径检查，长链接地址优先用短而清楚的链接标签。

超长说明移到表外段落，使用可读小标题或链接对应；不要机械截断作者原文、数字或重要限制条件。
也不要把单个长论述拆成没有意义的多行表格。表格用于对比、映射和查阅，段落用于解释。

## 开源工作：论文—代码标注为必做

公开代码可获得时，必须检查适用的五类核心流程；论文不涉及某类时说明证据与不适用原因。
无法访问、尚未找到或不能确认的实现属于未解决缺口。已证实的未公开实现或论文代码差异，
有可回查依据并经独立核验后属于阅读发现；不能因此宣称代码完全一致，也不能伪装成不适用。

| 类别 | 颜色 | 必查内容 |
|---|---|---|
| 输入与预处理 | YELLOW | 输入、数据转换和依赖的前处理 |
| 模型与核心结构 | BLUE | 主要表示、模块和论文创新 |
| 训练与主要损失 | ORANGE | 参数、监督、损失和更新；区分训练与逐场景拟合 |
| 推理与优化 | GREEN | 测试流程、优化阶段与输出 |
| 评价与指标 | PURPLE | 论文采用的指标及评测实现 |

每个对应都要三处一致：`paper_annotated.pdf` 在对应原文位置含论文标题、章节/公式、颜色、真实代码与中文解释；
源码普通中文注释指向相同论文标题、章节/公式和 PDF 路径；`code_map.md` 写准确文件/函数/行范围与解释。
不生成额外映射流水号或机器注释边界。JSON 映射用 `paper_title`，每项由 `paper_location` 与 `code_file` 定位。
不能只在 PDF 加一张说明页、只写映射表、仅列函数名或用伪代码代替原实现。
评价以论文实际采用的指标为准，不预设所有论文都必须使用某个指标。论文与代码存在实质差异时保留原文译文，
另列实现差异、证据与影响。尚未核实的缺口保持 partial / blocked；已核实差异不阻止阅读收尾，
不为通过阅读验收修改算法。

标注源于逐块阅读真实代码。复制片段必须逐字对应所选代码版本，解释输入、输出及与论文公式/步骤的关系；
源码注释遵循文件语言。保留可核对的干净基线，直接在现有源代码文件的关键代码块旁添加中文解释性注释；
不逐行注释、不重构、不改变执行逻辑，无需为此创建或切换专用分支。
注释后更新行范围，检查差异与语法；PDF 逐处核对位置、颜色和可读性。操作副本，不覆盖原 PDF 或个人批注。
详细格式见项目 `related_work/code_annotation_guide.md`。

静态阅读完成不要求安装所有训练依赖、运行实验或复现指标。运行情况单独记入复现报告；
静态对应、可运行性和结果复现是不同的证据，不能互相替代。

## 验收与未完成状态

新条目由工作流生成未完成的 manifest 骨架，Agent 按实际核查填写；脚本校验内容和生成 HTML，
不会自动决定语义上是否完成。命令形式如下，开源条目应提供关联 reproduce 条目。

```bash
python <skill>/scripts/reading_artifacts.py render <paper-dir> --repo-entry <reproduce-entry>
python <skill>/scripts/reading_artifacts.py check <paper-dir> --repo-entry <reproduce-entry>
```

无公开代码的工作省略 `--repo-entry`，在记录中说明检索依据。不要编造仓库或缺少证据就宣称不开源。

必须同时满足结构核查、作者自检和未参与写作的子代理独立核验，才可报告阅读完成。
工具能检查文件、章节、空占位、表格长度与部分产物关联，不能证明译文忠实或映射语义正确。
核验者回查原文、真实代码和可视化标注，逐项核验详细 note 的机制解释、公式、数字、比较和结论边界，
以及 qa 六问的完整答案与依据，并核对 note 英中 Highlights 的逐条对应与 translation_zh 一致性。
复用内容还须核对论文身份、纠错和材料区必要归属；问题交作者修复后再次核验。
JSON 中自报 complete、`workflow_ready=true` 或 shell 返回成功，都不能单独成为独立核验的证据。

阅读状态与实现一致性分别记录。manifest 中 `gaps` 仅存未解决缺口；已独立核实的真实差异存入
`verified_differences`，每条含 `description` 和可回查的项目内文件 `evidence`，可以带锚点。
manifest 用 `paper_title` 标明论文；`review` 只保留 `status`、`reviewed_at` 和不含内部标识的 `evidence`，
核验者身份与完整审阅报告写唯一内部状态文件。覆盖项使用 `locations` 列出实际章节/公式名称，与映射位置一致。
存在已核实差异时，代码状态可为 `differences_verified`，覆盖项可为 `difference`，须给真实论文位置与说明。
不能自动把旧 gaps 迁成已核实差异，也不能用空说明免除适用类别的阅读。
检查报告分别返回 `reading_status` 与 `correspondence_status`；只有结构有效、语义核验记录有效且无未解决缺口，
才可能返回 `workflow_ready=true`。主代理还须确认核验者独立、针对当前修订且返修已完成。

未完成时标 `partial` 并列出缺项；依赖材料或外部条件无法继续时标 `blocked`，写清证据、影响和下一步。
不能通过删必需章节、把适用项目改为不适用、保留 TODO 后宣布通过，或把结构检查结果描述成语义审核通过。
“原文未明确讨论”“本项目未运行”等有具体范围的诚实声明不等于模板未填，不应为了检查而删除。

完成前还须复查执行标识泄漏：检查本次生成或迁移的阅读交付路径、正文、JSON、HTML 属性、源码及 PDF 属性，
确保唯一内部状态文件以外没有本流程生成的执行标识；本次新增临时副本或缓存同样遵守。
扫描针对本工作流生成的内部标识；不删除合法 DOI、arXiv、commit、原文编号、已有函数变量名或可读方法名。
本次只迁移阅读产物与新 workflow，保留其他任务上下文和既有历史备份，不进行全项目历史清理。
