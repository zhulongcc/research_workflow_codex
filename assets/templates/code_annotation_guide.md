# Paper—code annotations

> 公开代码工作的必需阅读交付。PDF、源码与 code_map 使用论文标题、章节/公式和代码位置相互定位。
> 论文里能查到代码，代码里能找回论文位置；完整门槛见 `reading_standard.md`。
> 执行先后与独立核验见 [reading_workflow.md](reading_workflow.md)：先读懂代码，再注释和标注，随后修订 note。

## 必查范围

| 颜色 | 核心类别 | 内容 |
|---|---|---|
| YELLOW | 输入与预处理 | 输入、数据转换和外部前处理 |
| BLUE | 模型与核心结构 | 表示、关键模块与论文创新 |
| ORANGE | 训练与主要损失 | 参数、监督、损失和更新 |
| GREEN | 推理与优化 | 测试或逐场景优化、输出 |
| PURPLE | 评价与指标 | 论文实际采用的评价与代码实现 |

颜色区分类别，可读模块名和原文章节/公式定位具体内容；不生成模块流水号或机器标记。
`code_map.md` 与 `paper_code_annotations.json` 使用相同的论文位置和代码路径。
五类均须检查，适用类别至少有真实核心对应。论文不涉及的类别说明原文依据后可标 not_applicable；
仓库不能访问、还没读完或无法确认的对应属于未知缺口，不能标成不适用。
已证实的缺失实现或真实差异，经独立核验后作为阅读发现；保留证据，不阻止阅读收尾。
阅读完成与代码完全一致分开记录，未确认缺口仍为 partial / blocked。
表格行的全部可见文字合计 ≤160 字符，长文件路径与解释放表外并使用短链接。

## 论文侧

在对应段落、公式、算法框或图示处高亮，批注写 **论文标题、章节/公式、文件/函数、真实代码片段和中文说明**。
代码取自已核查版本的关键几行，保留缩进，不用伪代码或文件名代替实现。
说明这一段的输入输出与论文关系；既记录对应也记录实现差异。

输出 `paper_annotated.pdf`，必须与 `paper.pdf` 是同一版；不改正文、不盖住内容、不清除个人批注。
不能只加总览页或附件而不在原文对应位置批注。已有个人批注的文件不要覆盖，使用新副本。

逐项填写 `paper_code_annotations.json` 的真实定位后，可用 workflow 的工具生成标准 PDF 批注：

```bash
python <skill>/scripts/annotate_paper.py --pdf <paper-dir>/paper.pdf \
  --repo <reproduce-entry>/repo --map <paper-dir>/paper_code_annotations.json \
  --output <paper-dir>/paper_annotated.pdf
```

映射格式见技能包 `examples/paper_code_annotations.template.json`。模板默认未核验；
只有实际读过论文与代码后才填写并标记 verified。工具成功不等于语义对应成立，仍须复核。
映射使用 `paper_title`；每项通过 `paper_location` 和 `code_file` 定位，另记准确行范围及函数。
不保留内部执行标识或额外映射标识，PDF 批注正文、标题、作者字段和其他属性也不得残留这些值。

## 代码侧

直接在现有源代码文件的关键代码块旁添加中文解释性注释，不逐行注释，不重构、不改变行为。
无需为阅读注释创建或切换专用分支，不自动提交或推送。
记录采用版本和完整 commit，保留干净基线；不记录 SHA256。

```python
# 论文对应：<论文标题>｜<章节标题/公式>；<同版 PDF 相对路径>
# 含义：这段代码做什么，输入输出是什么。
# 此处保留原始代码，不改计算逻辑。
```

源码用普通中文解释注释指向可读论文标题、真实章节/公式和 PDF 路径；不依赖编辑器配色或机器边界标记。
按文件语言采用正确注释语法，不添加内部任务、作者或核验者标识。
注释后检查 diff，确保只新增注释，并更新映射行范围；必要时做语法检查。
逐块核对实际数据流、参数和公式，不能只凭函数名猜对应。
不要求为了静态阅读跑完整实验；未运行与未复现状态应如实写入复现报告。

## 完成前复核

1. 原始 PDF、批注 PDF 是选定同版；逐处检查高亮位置、颜色、可读引用和文本可读性。
2. 批注中的真实代码片段与选定代码版本一致，源码注释指回准确的论文位置。
3. `code_map.md`、JSON、PDF 与源码中的论文标题、章节/公式、代码位置一致，注释后的行范围准确。
4. 五类覆盖中的真实差异与未确认缺口分开，前者有定位、影响和证据，后者保持 partial / blocked。
5. 运行 `reading_artifacts.py check <paper-dir> --repo-entry <reproduce-entry>`，完成作者自检。
6. 由未参与写作的子代理核验原文、代码、标注与已知差异；问题交作者修复后重做检查，再核验当前修订。

自报 verified、manifest complete 和脚本通过都不能代替内容核查。
本规范要求的是静态对应；不要声称已经训练、复现指标或确认数值一致。
审阅意见与返修过程存唯一内部状态文件，读者正文只保留最新对应、真实差异和局限。
收尾时按执行规范检查路径、正文、元数据、源码及 PDF 属性，确保执行标识只存在于 `.workflow/execution_state.json`。

## Zotero

把标注 PDF 作为原论文条目的另一附件打开，不覆盖已有笔记。
外部批注可查看；要编辑，在阅读器中用 File → Import Annotations。导入会将批注移到 Zotero 数据库，
并从该 PDF 移除，所以操作副本。代码是批注里的普通文本，不保证语法高亮。

依据：[Zotero 官方说明](https://www.zotero.org/support/kb/annotations_in_database)。
有真实 PDF 和代码后才标注；完成后逐页核对位置、颜色与内容，不把模板当成果。
